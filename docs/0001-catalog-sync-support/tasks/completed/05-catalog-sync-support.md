## Цель

Обеспечить публичным API пакета full/backfill/incremental-синхронизацию каталога Poizon, получение описаний и проверку цен без собственного транспорта и подписи в приложении.

## Объём

- Добавить в `SpuListQuery` параметры `querySku`, `modifyStartTime`, `modifyEndTime`, в `SkuListQuery` — `modifyStartTime`, `modifyEndTime` по принятому контракту спайков. Новые аргументы добавить в конец конструкторов. Для новых параметров конструктор и `fromArray()` должны одинаково валидировать типы и трактовать `null` как отсутствие; `false` сохраняется в запросе и подписи. Существующие вызовы сохраняют совместимость.
- Применить принятое решение спайка 03: не вводить автоматическое снятие/удаление SKU, не использовать deprecated distStatus как надёжный фильтр. Сохранять сырые поля и документировать неизвестность снятия до подтверждения Poizon.
- Применить выводы спайка 03 о `minBidPrice` и изменении `modifyTime`. Описать подтверждённый способ получения цен: через списки либо существующий `querySkuBidPrice` и отдельный обход в приложении. Не считать неподтверждённые предположения контрактом.
- Применить подтверждённое спайком 04 представление каналов global/fast публичными параметрами SDK и OAuth-подключениями. Если нужны общие возможности протокола, включить их в выпуск; семантику каналов и выбор авторизаций оставить приложению.
- Документировать `lastId`, `hasMore`, `total`, `extraFields`, различие отсутствующего поля и явного `null`, строковые идентификаторы и точные цены в исходных единицах. Расширять типизированные поля ответов только там, где подтверждённый контракт невозможно корректно использовать через существующий публичный API.
- Дополнительно принимать числовой `Spu.distSpuId`, возвращая строку без преобразования через float; существующие строки сохранять.
- Переиспользовать транспорт, подпись, OAuth и DTO. Передавать UTC-миллисекунды без пересчёта часового пояса и угадывания секунд. Не ужесточать прежнюю валидацию скрыто в совместимом выпуске; необходимые несовместимые изменения выделить отдельно.
- Обновить документацию параметров, временных окон, пагинации, описаний и каналов. Подготовить результат для отдельной проверки и публикации по задаче 06.

## Решения реализации

28.11.2026 реализован согласованный контракт с принятыми ограничениями спайка 03.

- `SpuListQuery` дополнен `querySku`, `modifyStartTime`, `modifyEndTime`; `SkuListQuery` — двумя временными границами. Новые входные аргументы принимаются как mixed до общей проверки InputValidator, чтобы слабый PHP-caller не преобразовал строку `"false"` в bool или float в int до валидации. Публичные readonly-свойства имеют типы bool/int|null; строковые Long нормализуются в int. Пример: querySku=false сохраняется в body/подписи; null новых полей исключён обоими путями создания; строка `"false"` вызывает InvalidRequestException.
- В каждом Query используется одна локальная схема для конструктора и fromArray. Старая валидация и порядок старых аргументов сохранены: SPU pageSize2000 по-прежнему проходит локально, хотя серверный предел200 задокументирован; явный null старого pageSize в fromArray остаётся ошибкой. Неизвестные/зарезервированные поля запрещены.
- `Spu::fromArray` локально преобразует неотрицательный int distSpuId в строку перед Hydrator. Пример: 12345 → `"12345"`; UUID/opaque и прежние пустые строки сохранены, отрицательный int/float/bool отклоняются. Общий Hydrator и декодер не менялись; большие JSON ID сохраняются без float.
- Транспорт, подпись, OAuth, типы дополнительных полей и бизнес-семантика сохранены. Основные цены читаются существующим querySkuBidPrice до 200 ID, без зависимости от modifyTime; автоматического снятия/удаления SKU и deprecated-фильтра SDK не добавляет. Кэшей, очередей, фоновых процессов и новых состояний нет.
- `CatalogSyncTest` добавляет 35 регрессионных случаев: слабые caller-типы, оба способа создания, окна/границы, старые вызовы, подпись/body, большие ID, присутствие/null и реальные формы цен/статусов/описаний. Минимальные очищенные HTTP-фикстуры лежат в tests/fixtures/catalog; источники и синтетические отличия описаны рядом. Все HTTP подменяются; внешняя сеть отключена.
- Обновлены публичный README, документация каталога и спецификация; приведены single-page full/backfill/incremental примеры с обязанностями приложения. На этапе задачи 05 возможности рабочего кода были явно отделены от ещё не опубликованного выпуска; публикация v0.1.1 выполнена позднее в задаче 06. Исторический сценарий04 сохраняет прежний отказ числового distSpuId и помечен baseline-ревизией, первичные JSONL не менялись.
