## Цель

Установить рабочий способ обновления цен и обнаружения снятых SKU в новом протоколе, не перенося неподтверждённую семантику legacy API.

## Методика и контрольные примеры

1. На заранее выбранных SKU с предложением и без него сопоставить `minBidPrice` списков, вложенных SKU и `querySkuBidPrice` для одной авторизации. Контрольные кандидаты из прежнего протокола — `65412613`, `65412626`, `65412648`; их текущую пригодность перепроверить.
2. Для метода цен выполнить запросы с `hasPrice=true`, `false` и без него. Сравнить состав `data.items`; установить допустимый размер `dwSkuIds`, валюту и единицы цены по источникам и проверке.
3. Различить отсутствующий элемент, отсутствующее поле цены, явный `null`, ноль и положительную цену. Не трактовать ошибку чтения как отсутствие предложения.
4. Наблюдать реальные изменения цены, исчезновение и появление предложения на контрольных SKU; сравнить `modifyTime` и попадание в временную выборку до/после. Не менять upstream-данные для эксперимента.
5. Проверить выдачу снятых SKU, применимость deprecated `distStatus` и действующий механизм обнаружения снятия. Отсутствие ценового предложения не равно удалению SKU из каталога.
6. Сохранить неизвестные гарантии переходов как неизвестные. По решению владельца 28.11.2026 принять консервативный контракт ниже и вынести официальное подтверждение в отдельную задачу, не блокирующую реализацию SDK.
7. Описать подтверждённый алгоритм: цены из списков либо отдельный обход `querySkuBidPrice` в приложении; способ обнаружения снятия. Если `modifyTime` не охватывает цены, явно предусмотреть отдельный периодический обход цен в приложении.

## Проверка

Для ненаблюдавшихся переходов явно зафиксированы отсутствие доказательств и принятые ограничения; стабильные снимки не считаются подтверждением перехода. Цены сохранены точно, без float. Неизвестный статус не считается успехом; снятие товара и отсутствие предложения различены.

## Вне объёма

Покупки, изменения каталога, финансовые расчёты, расписание обхода цен, внедрение старого фильтра и реализация SDK.

## Готово, когда

- Подтверждены способ получения цены, единицы и правила интерпретации результата.
- Принят безопасный контракт без гарантий ценовых событий через modifyTime и без автоматического обнаружения снятия: отдельное чтение цен, сохранение неизвестного состояния снятия, отсутствие бизнес-выводов из deprecated-статуса.
- Отчёт существует, доступен из README, выводы внесены в спецификацию и документацию пакета. Вопросы Poizon перенесены в отдельную задачу; завершение основано на решении владельца принять ограничения, а не на получении ответа.

## Фактический прогресс — 28.11.2026

- Созданы [отчёт](../../reports/03-prices-and-delisting.md), [очищенные наблюдения](../../reports/03-price-observations.jsonl), [живой сценарий](../../reports/scripts/03-live-prices.php) и [офлайн-проверки](../../reports/scripts/03-local-price-contract.php).
- Выполнены 24 живых read-only запроса через Fast/Global без refresh и записи credentials. В списках/вложенных SKU контрольных товаров цены отсутствуют; `querySkuBidPrice` различает элементы с ценой и без неё через `hasPrice`. Массив 200 ID принят, 201 отклонён бизнес-кодом. Девять офлайн-проверок SDK и Pint двух сценариев успешны.
- SKU без основного `minBidPrice` сохраняет `PRODUCT_ON`; уточняющие чтения показали пустой `supplementPrice`. Поиск SPU с `distStatus=PRODUCT_OFF` вернул запись `PRODUCT_ON`; аналогичный единичный SKU-запрос завершился ошибкой декодирования без зафиксированного HTTP-кода, не повторялся. Реальный переход цены/доступности или снятия за интервал не наблюдался; гарантии обновления `modifyTime` и получения снятых SKU не установлены. В отчёте подготовлены вопросы Poizon на китайском с русским переводом, без отправки.
- Первоначальная блокировка 05/06 снята решением владельца 28.11.2026: исследование принято с ограничениями. Стабильные снимки по-прежнему не доказывают поведение переходов.

## Решения реализации

Принято с ограничениями 28.11.2026 по поручению владельца перейти к реализации до ответа Poizon. Цены читаются отдельно через существующий `querySkuBidPrice` (до 200 ID), без гарантии полноты цен через modifyTime. Например, PRODUCT_ON у SKU 65412648 не даёт основания считать основную цену доступной. Отсутствие цены/записи incremental не является снятием SKU; deprecated-фильтр не используется как надёжный источник удаления. Продуктовые классы в спайке не менялись, новых состояний/кэшей/очередей SDK не вводится.

Неизвестные гарантии и подготовленный CN/RU запрос сохранены в [отчёте](../../reports/03-prices-and-delisting.md); их последующее уточнение ведётся в [задаче бэклога 02](../../../0000-backlog/tasks/02-confirm-price-and-delisting-contract.md), не блокирующей 05/06. Решение включено в спецификацию и документацию пакета.
