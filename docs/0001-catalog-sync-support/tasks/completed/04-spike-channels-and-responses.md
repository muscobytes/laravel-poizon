## Цель

Проверить представление Fast/Global через существующий OAuth API SDK и установить минимальные совместимые изменения форматов ответов для каталога.

## Методика и контрольные примеры

1. Через существующие авторизации Fast и Global выполнить одинаковые чтения SPU, SKU, карточки и цены по одним dw ID. Результаты связывать с обезличенным псевдонимом подключения.
2. Проверить, достаточно ли `AuthorizationReference` без `distPlatform` и других параметров. Не угадывать enum; необходимость дополнительного параметра подтверждать источником и сравнением ответов.
3. Сопоставить dw/dist ID между подключениями. Различия dist ID не трактовать как разные товары. Зафиксировать `fulfillmentMode`; не использовать его как замену канала Fast/Global.
4. Сверить числовой и строковый `Spu.distSpuId`, типы остальных ID и реальные структуры ответов. Проверить воспроизводимость ответа через DTO. Если вариант не наблюдается, обозначить это; заявленную поддержку подтвердить документацией и отдельной синтетической регрессией, не выдавая её за живое наблюдение.
5. Изучить описания (`productDesc` и фактически возвращаемые поля), вложенные SKU, атрибуты, неизвестные поля, отсутствующие значения и явный `null`. Проверить достаточность `extraFields`, `has()` и `fields()`.
6. На очищенных примерах отдельно проверить ID `9007199254740993` (больше `2^53`) и `9223372036854775808` (больше signed 64-bit). Для декодера использовать также JSON с числовым литералом, а не только уже строковым значением. Это синтетическая проверка сохранения точности, не свидетельство реального значения Poizon.
7. Перечислить только необходимые общие изменения SDK; выбор подключений и бизнес-сопоставление каналов оставить приложению.

## Проверка

Оба подключения доступны и сопоставлены по одному dw ID. Разделены живые наблюдения, документированные типы и синтетические регрессии. Нет преобразования ID через float и догадок о семантике `fulfillmentMode`.

## Вне объёма

Создание/смена авторизаций, миграция ключей каталога, объединение предложений Fast/Global и реализация SDK.

- Отчёт существует, доступен из README, выводы внесены в спецификацию и документацию пакета.

## Решения реализации

Выбор авторизации достаточен в проверенной матрице Fast/Global; distPlatform не добавляется. productDesc доступен через extraFields, неизвестные/null-поля сохраняются. Пример: один dwSKU имеет разные UUID dist ID в двух авторизациях; числовой Spu.distSpuId=12345 сейчас ProtocolException и остаётся совместимым расширением задачи 05. Продуктовые классы SDK не изменялись. Исследовательские сценарии и очищенные наблюдения хранятся в reports/ проекта; они запускаются вручную, не создают кэш или credentials и не подключаются к CI. Результаты отражены в [документации пакета](../../../catalog-sync.md) и [спецификации](../../spec.md).
