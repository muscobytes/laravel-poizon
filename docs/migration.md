# Будущий переход со встроенного пакета

Эта заметка описывает отдельную работу в приложении. Сам перенос репозитория приложение не изменяет.

1. Удалите `path`-репозиторий `packages/poizon` из Composer приложения, замените зависимость `raketa/laravel-poizon` на `muscobytes/laravel-poizon:^0.1` и обновите lock-файл.
2. Замените импорты `Raketa\Poizon` на `Muscobytes\Poizon`, включая providers, listeners и container bindings по именам классов. Совместимых алиасов нет.
3. Сохраните конфигурацию `poizon.*`, переменные `POIZON_*`, строковый binding `poizon.logger`, scheduler и `APP_KEY`. Дефолт retry пакета остаётся `false`; опубликованная конфигурация приложения имеет приоритет.
4. Сохраните таблицы, IDs, ciphertext и запись миграции `2026_11_17_210000_create_poizon_authorizations`. Удалите локальный дубликат миграции, если он есть; не запускайте повторное создание таблиц и не переименовывайте миграцию.
5. Нормализация legacy-причин `problem_reason` остаётся ответственностью приложения. Сохраните его миграции преобразования данных.
6. Выполните интеграционные тесты приложения, включая PostgreSQL-конкурентность и расшифровку существующих credentials. Проверьте production-сборку без локального path-пакета, затем удалите встроенную копию.

Откат требует возврата Composer-зависимости и импортов. Схема данных при переносе не меняется; прежний `APP_KEY` необходим в обоих вариантах.
